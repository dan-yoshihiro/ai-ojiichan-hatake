# pages.dev のサイトが Google に5ページしか登録されていなかったら、何を確かめるか：サイトマップ「取得できませんでした」の記録

*最終更新: 2026-11-14 / 観測: Search Console 直近3か月（2026-08-11〜11-10）、Cloudflare の Logs 直近30日*

> **TL;DR:** Search Console で見ると、このサイトは3か月で検索結果に39回表示され、クリックは1回でした。サイトマップに載せた17件のうち、Google に登録されていたのは5ページだけです。サイトマップは「取得できませんでした」のままでした。ファイルはブラウザから正しく開け、Cloudflare の Logs には Google からサイトマップへのリクエストが1件も残っていません。本物の Googlebot が来たのも30日で1回でした。なぜ取得できないのかは、まだ突き止めていません。その間に、登録リクエストと、外のサイトからの入口づくりを進めました。

Cloudflare Pages の `*.pages.dev` のままサイトを運用していて、Search Console の数字が増えない人向けです。[アクセスの8割がエラー応答（4xx）だった記録](/cloudflare-traffic-recheck)と同じ日に調べた続きです。

## Search Console では、検索にどれくらい出ていたのか

ほとんど出ていませんでした。Search Console（Google が検索での見え方を教えてくれる無料の管理画面）の直近3か月の数字です。

| 項目 | 値 |
|---|---:|
| 合計クリック数 | 1 |
| 合計表示回数 | 39 |
| 平均 CTR（表示に対するクリックの割合） | 2.6% |
| 平均掲載順位 | 66.2 |

検索語は4つ出ていました。「x 頻度 分析」が19回、「ツイート 回数 分析」が5回、「x レビュー 分析」が4回、「twitter 頻度 分析」が2回で、合わせて30回です。残りの9回は、Search Console が検索語を出さない分でした。

ページ別では、[週1回の振り返りシート](/sns-weekly-review)が35回、トップページが4回（クリック1回はここ）、ほかの2ページが1回ずつです。ページ別に足すと41回で、全体の39回とは一致しません。

平均66位は、検索結果の7ページ目あたりです。表示されても、まず見られない位置です。

## なぜ17件中5ページしか登録されていないのか

多くのページは、Google にまだ存在を知られていませんでした。Search Console の「ページのインデックス登録」では、登録済みが5ページ、未登録が2ページです。未登録の2ページの理由は「クロール済み - インデックス未登録」で、Google が読んだうえで登録しなかったページです。サイトマップには、`llms.txt` を含めて17件を載せています。残りの10件は、Google の手元にありません。

主なページを URL 検査（1ページずつ Google での状態を見る機能）で確かめると、こう分かれました。

| ページ | 状態 |
|---|---|
| トップ | 登録済み |
| [6か月のまとめ](/ai-x-operation) | 登録済み |
| [週1回の振り返りシート](/sns-weekly-review) | 登録済み |
| [運営者について](/about) | 登録済み |

| Cloudflare の技術記事3本 | 未登録 |

週ごとの記録の各ページは、検査していません。

[インプレッションが減ったとき](/x-impressions-drop)の検査結果には、「参照元サイトマップが検出されませんでした」と「参照元ページ：検出されませんでした」が出ていました。サイトマップからも、ほかのページのリンクからも、まだたどられていないということです。

送ったサイトマップは2つあります。`/sitemap.xml`（最終読み込み 2026年10月31日）と `/sitemap.xml?v=2`（同 9月27日）で、どちらも「取得できませんでした」、検出されたページは0でした。

## サイトマップの「取得できませんでした」は、何が原因なのか

まだ分かっていません。分かったのは、ブラウザから開くとファイルが正しく返ることと、Google から取りに来た記録が Cloudflare に残っていないことです。Googlebot から見て同じように返っているかは、確かめられていません。

ファイルは、ブラウザから `/sitemap.xml` を開くと 200（正常）で返り、種類は `application/xml` でした。XML の検証ツール（`xmllint`）でも誤りは出ません。`robots.txt` にもサイトマップの場所を絶対 URL で書いてあり、Googlebot は許可しています。

次に、Cloudflare の Observability の Logs で、直近30日のリクエストのうち `sitemap` を含むものを並べました。7件ありました。

- ウクライナの1つの IP から3件
- アメリカの IP から2件
- ロシアの IP から1件
- シンガポールの IP から1件（http で来て、301 で https へ転送）

Google のクローラーがよく使う `66.249.` で始まる IP は、1件もありません。Search Console の最終読み込みは10月31日ですが、その日にも見当たりませんでした。

User-Agent（ブラウザや道具が名乗る名前）に「Googlebot」を含むリクエストも探しました。30日で4件です。

| 日時（日本時間） | パス | 送信元 |
|---|---|---|
| 10月22日 13:09 | `/robots.txt` | `66.249.` で始まる IP（アメリカ） |
| 10月31日 12:08 | `/.env.old`（404） | Cloudflare のネットワークの IP（ドイツ） |
| 10月31日 12:14 | `/x-impressions-drop` | 同じ IP（ドイツ） |
| 11月6日 17:00 | `/` | Cloudflare のネットワークの IP（フランス） |

Google が `/.env.old` のような秘密のファイルを探しに来ることはありません。10月31日の2件は、Googlebot を名乗っているだけの機械です。11月6日の1件も同じ範囲の IP から来ています。Google のものと見てよいのは、10月22日に `robots.txt` を読んだ1件だけでした。

Search Console は「10月31日に読もうとして失敗した」と言い、Cloudflare の Logs にはその記録がありません。この食い違いの理由は、まだ説明できていません。Cloudflare に届く前に失敗したのかもしれませんし、Logs に残らない形のリクエストがあるのかもしれません。確かめるには、Search Console からサイトマップを送り直し、その日の Logs を見るのが早いと考えています。次に試すことです。

Logs に残っている範囲では、30日のあいだ、Google がこのサイトの記事を取りに来た記録は1つもありません。

## 登録リクエストは、すぐに送れたのか

送れませんでした。未登録のページは、URL 検査から1件ずつ「インデックス登録をリクエスト」で Google に知らせられます。2026年11月14日にこの画面から送ったところ、「1日の割り当て量を超えています」と出て、受け付けられませんでした。同じ日にほかで何件送られていたかは分かっていません。

送れなかった5ページ（インプレッションが減ったとき、週ごとの実測の一覧、Cloudflare の技術記事3本）は、翌日に送り直します。結果はこの記事に追記します。

## Google に見つけてもらう道を、外にどう作ったか

note・Zenn・Qiita の3つのサイトから、このサイトへリンクを張りました。登録リクエストは1ページずつの応急処置なので、Google がよく巡回する場所からのリンクで、見つけに来る道を増やすためです。人がたどる入口にもなります。

| 入口 | 中身 | リンクに付けた印 |
|---|---|---|
| note の記事5本 | 自己紹介の記事と、内容が重なる記事 | `?utm_source=note_article` |
| [Zenn の記事](https://zenn.dev/ai_ojiichan/articles/fdc8d189991697) | 4xx が8割だったときの調べ方 | `?utm_source=zenn` |
| Zenn のプロフィール | ウェブサイトの欄 | `?utm_source=zenn_profile` |
| [Qiita の記事](https://qiita.com/ai_ojiichan/items/3675d0cab476a3ee7740) | 自前のアクセスログでボットを見分ける作り方 | `?utm_source=qiita` |
| Qiita のプロフィール | サイトの欄 | `?utm_source=qiita_profile` |

印（`utm_source`）は、リンクを貼った場所を URL に書いておく目印です。ページの表示には影響しません。

Zenn と Qiita には、同じ記事を載せていません。Zenn は[4xx が8割だった件](/cloudflare-traffic-recheck)の要約、Qiita は[ボットと自分のアクセスを除外する方法](/cloudflare-bot-detection)の要約です。同じ内容を2か所に置くと、検索では重複として扱われやすく、両方を読む技術者には同じ話に見えるからです。どちらも要約だけで手順やコードを持ち帰れるように書き、このサイトへのリンクは最後に置きました。

X には貼っていません。X のフォロワーは家庭菜園が目当ての人が中心で、AI に投稿を任せた運用の記録には誘わないと決めています。

比べるための出発点として、同じ日の直近30日の数字を残しておきます。運営者・ボット・200 以外の応答・画像などの静的ファイルを除いた閲覧の、参照元ごとの件数です。

|---|---:|

| サイト内の移動 | 225 |
| www.google.com | 14 |

「参照元なし」には、1つの IP がサイトの全ページを順に開くような閲覧も含まれています。www.google.com の14件も、[前の記録](/cloudflare-traffic-recheck)で見たとおり、ほとんどがサイト名で検索して巡回する道具でした。この表は人の数ではなく、あとで比べるための基準です。

## 同じ状態のサイトでは、何から確かめればいいか

1. Search Console の「ページのインデックス登録」で、登録済みと未登録の合計が、サイトマップの件数より少なくないか見る。少なければ、Google が知らないページがある
2. 主なページを URL 検査にかけ、「参照元サイトマップ」「参照元ページ」が検出されていないページがないか見る
3. サイトマップが「取得できませんでした」なら、ブラウザで開いて 200 と XML の正しさを確かめる。そのうえで、Cloudflare の Logs に Google からのリクエストが来ているかを見る
4. User-Agent に Googlebot を含むリクエストは、送信元の IP まで見る。名乗っているだけの機械が混ざる
5. 未登録のページは URL 検査から登録をリクエストする。1日の上限があるので、読ませたい順に送る
6. 外のサイトからリンクを張る。張るリンクには `?utm_source=` を付け、場所ごとに値を変える

## 分かったことと、まだ分からないこと

分かったことです。

- 3か月で検索の表示は39回、クリックは1回。ページ別では、表示の35回が週1回の振り返りシートだった。
- サイトマップの17件のうち、Google に登録されていたのは5ページ。Google の手元にあるのは7ページだけだった。
- サイトマップのファイルは、ブラウザからは正しく開ける。直近30日、Cloudflare の Logs に Google からサイトマップへのリクエストは無く、Google のものと見てよい訪問は `robots.txt` への1回だけだった。
- 登録リクエストは、送った時点で1日の上限に当たっていた。

まだ分からないことです。

- Search Console の「取得できませんでした」と、Logs に記録が無いことの食い違いの理由。サイトマップを送り直した日の Logs で確かめます。

- note・Zenn・Qiita のどの入口から、人が来るか。2〜4週間後に、印ごとの件数をこの記事に追記します。

自分を除き、ボットを除いて読者を数え直してきましたが、その前に、Google から見つけてもらえていませんでした。入口を作ったあとに増えるのが人なのか、また機械なのかは、数えてみるまで分かりません。
